# Teddy 1.2.0 计划

## 目标

1. 把浏览器侧固定凭据改成后端鉴权和随机短期会话。
2. 把 JAR 上传、删除和 Spark 提交限制在共享 lib.home 边界内。
3. 让 YARN 查询有超时、有故障转移，并明确区分过渡、成功、失败、人工停止和未知状态。
4. 把构建、升级预检、发布包自检和 ApplicationId 验收变成可重复脚本。
5. 周末只做仓库、隔离测试、文档、提交和推送；不连接或改动生产环境。

## 执行阶段

1. 基线与测试边界：已完成。
2. 后端鉴权、会话和 JAR 安全边界：已完成。
3. YARN 状态、重启、告警和提交失败清理：已完成。
4. 发布自检、升级演练和只读验收：已完成。
5. 全量构建、文档和分阶段提交：已完成；最终复核通过后推送隔离分支，不创建标签。

## 不变边界

- 不升级 Java、Spring Boot、Spark、MyBatis 或前端技术栈。
- 不改变现有 API 外层 state/data 格式。
- 不连接生产 MySQL、YARN、Webhook 或 Teddy。
- 不停止、提交、重启或删除任何生产任务。
- 不创建正式标签；正式发布和生产升级由用户在周一批准。

## 周一需要用户确认

- 选择登录用户名并在本机生成密码哈希，明文密码不进入仓库或聊天。
- 根据浏览器实际是否通过 HTTPS 访问，确认 auth.cookie.secure。
- 确认生产升级窗口、当前 ApplicationId 数量和最终发布版本号/标签。

其余代码、测试、产物检查、升级预检和验收命令应在周末准备完成。
