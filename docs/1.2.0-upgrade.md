# Teddy 1.2.0 升级与验收

本手册适用于已经完成版本化目录迁移的 1.1.0 环境。升级脚本只停止和启动 Teddy JVM、切换 current/previous 链接并检查健康状态，不会停止或重新提交正在运行的 Spark application。

## 周一前置决策

1. 在本机运行以下命令，输入新登录密码，只复制输出的哈希：

    .\tools\New-TeddyPasswordHash.ps1

2. 在生产共享 teddy.properties 中加入：

    auth.username=teddy
    auth.password-hash=上一步输出
    auth.session.ttl-seconds=28800
    auth.cookie.secure=false

auth.cookie.secure 在浏览器通过 HTTPS 访问 Teddy 时应设为 true；通过 HTTP 访问时必须为 false。lib.home 必须是 releases 目录之外的现有可写绝对路径。

新超时参数都有兼容默认值，可按需加入：

    spark.submit.app-id-timeout-seconds=120
    yarn.http.connect-timeout-ms=3000
    yarn.http.read-timeout-ms=5000
    yarn.command=yarn
    yarn.kill.timeout-seconds=30

## 发布包校验

本地构建会自动执行测试和发布包自检：

    .\tools\build-release.ps1

上传 tar.gz 与 SHA256SUMS 后，在服务器校验选中的包，再解压到 releases：

    grep -F 'teddy-1.2.0-release.tar.gz' SHA256SUMS | tr -d '\r' | sha256sum -c -

当前开发产物仍带 SNAPSHOT；未获得用户批准前不要改正式版本、打标签或部署。

## 升级前只读快照

验收脚本只调用健康接口、登录/退出、任务列表和 yarn application -status，不调用任务提交、停止或重启接口。

先准备一个权限为 600、且末尾没有换行的临时密码文件。不要把明文密码写进命令历史：

    umask 077
    read -r -s TEDDY_ACCEPTANCE_PASSWORD
    printf '%s' "$TEDDY_ACCEPTANCE_PASSWORD" > /var/tmp/teddy-acceptance-password
    unset TEDDY_ACCEPTANCE_PASSWORD

为本次窗口创建唯一目录，然后采集升级前快照。最近一次已知基线为 5 个 ApplicationId；如果周一实际任务数已变化，应先确认原因并调整预期值：

    acceptance_root=/var/tmp/teddy-1.2.0-$(date +%Y%m%d-%H%M%S)
    mkdir -p "$acceptance_root"
    TEDDY_AUTH_PASSWORD_FILE=/var/tmp/teddy-acceptance-password \
    TEDDY_EXPECT_APPLICATION_COUNT=5 \
    /usr/local/service/teddy/current/bin/acceptance.sh capture "$acceptance_root/before"

## 预检与升级

假设发布目录为 /usr/local/service/teddy/releases/teddy-1.2.0：

    /usr/local/service/teddy/releases/teddy-1.2.0/bin/upgrade.sh --preflight
    /usr/local/service/teddy/releases/teddy-1.2.0/bin/upgrade.sh

预检失败时不要绕过。修复共享配置、目录权限或发布包问题后重新运行。

## 升级后验收

    TEDDY_AUTH_PASSWORD_FILE=/var/tmp/teddy-acceptance-password \
    TEDDY_EXPECT_APPLICATION_COUNT=5 \
    /usr/local/service/teddy/current/bin/acceptance.sh capture "$acceptance_root/after"

    TEDDY_EXPECT_RELEASE=teddy-1.2.0 \
    /usr/local/service/teddy/current/bin/acceptance.sh compare \
    "$acceptance_root/before" "$acceptance_root/after"

通过条件：

- 健康接口为 UP，数据库检查为 UP。
- 升级前后的 ApplicationId 排序集合完全一致。
- 每个 ApplicationId 的 YARN 只读状态查询成功。
- current 指向 1.2.0，previous 仍指向可回滚的 1.1.0。
- 无重复提交、误重启或异常告警。

验收完成后删除临时明文密码文件：

    rm -f /var/tmp/teddy-acceptance-password

## 失败处理

升级脚本健康检查失败会自动恢复 previous。若升级脚本成功但验收对比失败，保留两个快照和日志，立即执行：

    /usr/local/service/teddy/current/bin/rollback.sh

回滚后再采集一次快照并与 before 对比。不要删除 previous 指向的版本或旧快照，直到问题定位完成。
